# Fixed writer → reviewer Node-RED example

Run `API_TOKEN=dev-token make demo-node-red-agents` from the repository root. This starts an isolated Compose project, publishes only the AaaS API at `127.0.0.1:3094`, waits for the private Node-RED flow, runs a typed HTTP walkthrough and tears down its containers. Requires Docker Compose, `ss`, curl, Node/npm and outbound model access. No provider credentials or host OpenCode installation are needed. Set `INTERNAL_TOKEN` to a value distinct from `API_TOKEN` to override the demo's internal checkpoint credential.

The Node-RED image pins Node-RED **5.0.7**, lockfile-installed `@tbrandenburg/node-red-agents` **0.4.2**, OpenCode CLI (`opencode-ai`) **1.18.33**, and model **`opencode/big-pickle`**. Both nodes use the direct runtime, `/data/agent-work`, one concurrent execution per node, one attempt and a 150-second node timeout. The API allows 360 seconds for the complete workflow. OpenCode Big Pickle does not require a provider account or API key.

The fixed workflow ID is `node-red-demo`; its public agent IDs are `writer` and `reviewer`. Start a workflow with `input: { "text": "Draft a release note" }`; optionally include `conversationIds: { "writer": "...", "reviewer": "..." }`. Omit both for fresh chats, provide both to continue both, or provide one to continue only that agent. The `202` and every run lookup include both public links (`writer-node` and `reviewer-node`). For direct chat, create a conversation with explicit `agentId: "writer"` or `"reviewer"`, then send a nonblank string message; or start an agent-targeted run with `{ "text": "..." }` and optional matching `conversationId`. The public conversation ID never equals the private OpenCode session ID.

One public workflow run starts one private HTTP request. Node-RED invokes writer first, validates its completed result and confirmed resume, builds the reviewer's actual prompt, and waits for an authenticated checkpoint acknowledgment on the separate, un-published Express port 3095 before invoking reviewer. The reviewer node is shared with direct reviewer chat; its incoming `sessionID` is explicitly replaced with the reviewer's own session. A confirmed writer reply and reviewer prompt remain in public history if reviewer fails. Transport disconnect/timeout is ambiguous: before checkpoint, the writer chat is readable but blocked for further execution until restart; after checkpoint, the reviewer chat is blocked instead. A late checkpoint cannot resume a terminal workflow. This is a disposable in-memory example; restarting loses histories, reservations and private session mappings.

Run/event/message reads are pollable. Cancellation, resume, SSE, artifacts, projects, interactions, mutable workflows, conversation edits/deletion and persistence retain typed `501` responses. Node-RED's HTTP and Admin APIs and the internal Express checkpoint listener are only accessible inside the Compose network.
